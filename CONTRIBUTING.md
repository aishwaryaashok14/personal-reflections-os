# Contributing to Personal Operating System Framework

Thank you for your interest in contributing! This framework thrives on community insights and improvements.

---

## How You Can Contribute

### 1. **Share Your Experience**

**What helps:**
- Post in Discussions about your discoveries
- Share what worked / what didn't
- Ask questions that help others
- Offer support to people just starting

**How:**
- Use GitHub Discussions
- Tag posts with relevant topics (e.g., "implementation," "exhaustion triggers," "family-anchored")

---

### 2. **Improve Documentation**

**What helps:**
- Fix typos or unclear instructions
- Add examples that clarify concepts
- Improve question wording in templates
- Create visual diagrams/guides
- Translate to other languages

**How:**
- Fork the repository
- Make your changes
- Submit a pull request
- Describe what you improved and why

---

### 3. **Add New Content**

**Domain-Specific Variants:**
- Questions for students, parents, executives, etc.
- Cultural-specific adaptations
- Profession-specific insights (founders, artists, engineers, etc.)

**New Tools:**
- Notion templates
- Obsidian templates
- Spreadsheet trackers
- Mobile-friendly versions
- Printable worksheets

**Additional Guides:**
- Specific topics (e.g., "Parenting & Personal OS," "Career Transitions")
- Deep dives on exhaustion triggers
- Case studies (anonymized)

**How:**
- Create new files in appropriate directories
- Follow existing formatting patterns
- Submit pull request with description
- Explain who would benefit and how

---

### 4. **Build Tools**

**We'd love to see:**
- Web apps that guide users through the process
- Mobile apps for daily/weekly check-ins
- Integrations with productivity tools
- Data visualization of patterns
- AI-assisted analysis tools

**How:**
- Build your tool (open source preferred)
- Link back to this framework
- Share in Discussions so others can use it

---

### 5. **Share Anonymized Examples**

**What helps:**
- Your completed personality architecture (anonymized)
- Before/after stories of implementation
- Specific exhaustion trigger solutions that worked
- Operating system designs for different life contexts

**How:**
- Anonymize all personal details
- Add to `examples/` directory
- Submit pull request
- Tag with relevant context (e.g., "parent-of-young-kids," "career-transition")

## Contribution Guidelines

### Quality Standards

**All contributions should:**
- Maintain the core principles (see README)
- Be inclusive and accessible
- Focus on self-knowledge over external advice
- Support multiple ways of being (no "one right way")
- Use clear, jargon-free language

### Formatting

**Markdown Files:**
- Use clear headers (##, ###)
- Include examples where helpful
- Break long text into readable chunks
- Use checklists for actionable items
- Add navigation links in longer documents

**Code/Tools:**
- Include README with setup instructions
- Add comments for complex logic
- Provide examples of usage
- List dependencies clearly

### Testing

**Before submitting:**
- Test your changes work as intended
- Have someone else review if possible
- Check links aren't broken
- Ensure formatting renders correctly

---

## Pull Request Process

1. **Fork** the repository
2. **Create a branch** for your changes (`git checkout -b improve-questionnaire`)
3. **Make your changes** following guidelines above
4. **Test** your changes
5. **Commit** with clear message (`git commit -m "Add parenting-specific questions"`)
6. **Push** to your fork (`git push origin improve-questionnaire`)
7. **Submit Pull Request** with description:
   - What you changed
   - Why you changed it
   - Who will benefit
   - How you tested it

## Types of Contributions

### ✅ Great Contributions

- New thoughtful questions for questionnaire
- Domain-specific adaptations
- Tools that help users implement the framework
- Clarifications of confusing sections
- Examples (anonymized) of completed analyses
- Translations to other languages
- Visual guides or diagrams
- Bug fixes in templates/tools

### ⚠️ Handle With Care

- Fundamental changes to core principles
- Adding complexity without clear benefit
- Prescriptive "you should" advice
- Product promotions or marketing
- Changes that assume one "right" way to live

### ❌ Won't Accept

- Spam or promotional content
- Divisive political/religious content
- Shaming or judgment of different approaches
- Privacy violations (non-anonymized personal data)
- Copyright violations

## Community Standards

### Be Kind

This framework is deeply personal. People are vulnerable when sharing their struggles and patterns. Respond with:
- Curiosity, not judgment
- Support, not fixing
- Shared experience, not advice-giving
- Respect for different paths

### Be Inclusive

People of all backgrounds, cultures, professions, and life stages use this framework. Avoid:
- Assuming everyone works corporate jobs
- US/Western-centric examples only
- Gendered language
- Ablest assumptions
- Economic privilege blind spots

### Be Honest

If something didn't work for you, say so! The framework evolves through honest feedback. Share:
- What you tried
- What happened
- What you learned
- What might work better
